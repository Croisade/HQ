# Decisions

- **2026-08-09** — TLS via an mkcert-issued internal CA, not Let's Encrypt. Actual Budget requires `SharedArrayBuffer`, which browsers only allow in a secure context — plain LAN HTTP doesn't qualify even with the right COOP/COEP headers. Let's Encrypt needs a publicly resolvable domain/DNS-01 challenge, which `thegarden` (LAN-only, not publicly routable) can't satisfy; mkcert's local CA works entirely offline. CA root lives at `data/mkcert-ca/` (gitignored), leaf cert at `data/certs/thegarden.pem` — a multi-SAN cert listing every `*.thegarden` hostname explicitly, not a wildcard (`*.thegarden` is a "second-level wildcard" that browsers/OpenSSL reject). Adding a new hostname means regenerating the cert with the name appended.
- **2026-08-11** — All routers use `entrypoints=websecure`+`tls=true`, none stay on plain `web`. The `web` entrypoint has a global HTTP→HTTPS redirect, so a `web`-only router becomes unreachable by hostname (redirects to `:443`, no router matches, 404) — learned the hard way when 8 newly-deployed services all 404'd until switched over.
